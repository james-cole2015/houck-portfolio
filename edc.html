Exposure Discovery Console

Structured CTEM discovery platform for client engagements

Built by a practitioner who needed it: a local application for running structured Continuous Threat Exposure Management discovery sessions — capturing stakeholder conversations across all six CTEM phases, assessing tool coverage, and producing AI-assisted SOW context without manual synthesis overhead.

Explore

The Problem

CTEM discovery sessions are high-value but structurally inconsistent. Without purpose-built tooling, both collection and synthesis fall apart.

No Repeatable Structure

Discovery conversations with client stakeholders happen across different roles and phases. Without a shared question bank and scoring model, every engagement starts from scratch and quality varies by consultant.

Stakeholder Availability Constraints

Key contacts — tool owners, operations leads, security managers — often can't participate in live sessions. There's no standard way to collect their input asynchronously and merge it back into the engagement.

Tool Inventory Is Unstructured

Clients maintain sprawling security tool portfolios with overlapping coverage and unclear ownership. Capturing rationalization data in a consistent, analysis-ready format during a live engagement is impractical without dedicated tooling.

SOW Synthesis Is Manual

Translating scattered discovery notes, SOW signals, and tool data into a coherent scope-of-work context takes hours of post-session synthesis that could be automated with the right structure in place during collection.

How It Works

A three-phase design separates preparation from live discovery and output generation, supporting both fully connected and offline engagement environments.

Discovery Wizard

Two navigation modes over the same question bank — choose the view that fits how the session is running.

Persona Mode

Organizes questions by stakeholder conversation — CISO, VM Lead, Operations, Cloud Security, and more. Designed for sequentially working through a set of planned interviews, with conversation summaries and notes between each group of questions.

Phase Mode

Reorganizes the same question bank by CTEM phase (PREPARE → IDENTIFY → PRIORITIZE → VALIDATE → MOBILIZE → REPORT). Useful when conversations don't follow persona boundaries, or for reviewing coverage gaps across a specific phase.

Per-Question Capture

Every question supports a 1–5 maturity score, rich-text notes (Quill editor), SOW signal tagging (Gap, Scope, Effort, Tool), flagging for unresolved items, and skip for out-of-scope questions. State is auto-saved and persists across restarts.

Offline Stakeholder Collection

Generates a self-contained Excel workbook with all discovery questions organized by CTEM phase. A stakeholder fills it in on their own time and returns it; the consultant imports responses directly into the active session as question notes.

Heatmap View

Visualizes session scores across the full CTEM phase × stakeholder conversation matrix. Surfaces coverage gaps and high/low maturity areas at a glance, providing a single-screen summary of where the client stands across the framework.

Admin & Customization

Operators can manage the question bank, add industry-specific tailoring entries, and configure SOW deliverable options through a built-in admin interface — without touching the source files or restarting the application.

Tool Intelligence

A structured workflow for capturing and analyzing the client's security tool portfolio — from intake through CTEM alignment.

Tool Registry

Tracks the client's full security tool inventory within the session. Each tool is categorized and linked to rationalization data collected through two separate workflows targeted at different audiences.

Client Assessment Workflow

A plain-language questionnaire the client fills in about each tool — ownership, deployment status, utilization, and perceived value. Can be completed live or via the self-contained stakeholder handoff form, requiring no CTEM knowledge from the client contact.

CTEM Tool Alignment

A consultant-completed assessment mapping each tool to CTEM phases, evaluating integration maturity, identifying consolidation candidates, and surfacing coverage gaps. Requires framework knowledge and cross-tool context only the consultant can provide.

Tools Analysis

Synthesizes rationalization data into three views: a phase coverage matrix showing which tools support each CTEM stage, a deployment maturity chart across the portfolio, and a ranked list of consolidation candidates with overlap descriptions.

Stakeholder Handoff Form

Generates a self-contained HTML form pre-populated with the client fields only. The client contact fills it out offline, downloads a JSON response file, and returns it. The consultant imports it to populate the Tool Registry without touching a spreadsheet.

AI Integration

AI assists with the highest-friction post-session task: synthesizing unstructured discovery notes into a structured scope-of-work narrative.

SOW Context Generation

The SOW export produces a structured markdown document containing discovery notes, SOW signals, scored findings, and tool data — formatted with the session context, proposed deliverables, and scope notes already embedded. Feed it to any capable LLM to generate a first-draft scope-of-work narrative without manual synthesis.

Works via the Claude API with a configured key, or as a prompt-ready export for any enterprise or air-gapped LLM. Includes a data classification notice reminding consultants to verify their LLM is approved before pasting client data.
Analysis Export for LLM Review

A dedicated analysis export combines session scores, engagement notes, and the full tool rationalization dataset into a prompt-ready format. Designed to be fed to an LLM for CTEM maturity gap analysis, consolidation recommendations, and programme prioritization insights.

Tool rationalization answers are labelled by source — client self-report vs. consultant assessment — so the LLM can weight input appropriately when generating recommendations.

Technical Highlights

Offline-first Runs entirely on the consultant's laptop with no server infrastructure or internet dependency
2 wizard modes Persona and phase views over the same question bank — switch without losing any captured data
6 CTEM phases Question bank spans PREPARE through REPORT with per-question phase tagging
5 export types SOW context, heatmap, tool inventory, analysis, and stakeholder questionnaire from a single session
Zero-dependency Quill and Chart.js bundled locally — no CDN calls, works fully air-gapped
Python + Flask Lightweight local server with native Win32 file dialogs — no tkinter, no database
